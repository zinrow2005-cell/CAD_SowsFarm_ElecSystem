# V11.6｜全場母系統、各棟舍子系統與設備連動

## 為什麼要修這一版

以前「系統模板與自動亮色對應」會在 CAD 上方固定鋪滿電路、水路、通風、飼料四張大卡片；四張卡片只統計有哪些設備類型，無法代表同一類型下各棟舍不同子系統，也佔用 CAD 的顯示空間。**V11.6 已移除該區塊和「四系統灰色模板／亮色」入口。**

原有的「放設備」、「畫水管」、「畫電線」、「畫飼料管」、設備清單與實際 CAD 圖層繼續正常使用；**新增的是獨立的系統架構管理，不是重畫底圖。**「我的設備模板」仍是可選用的單台設備外觀儲存工具，與已淘汰的四大系統卡片不同。

## 如何建立多棟舍的管理架構

1. 進入設備配置頁面，按左側 **「全場系統架構・棟舍子系統」**；手機從「系統架構」快捷入口開啟。CAD 圖面不會被固定模板壓縮。
2. 本機管理者模式下，新增一個真正的母系統，例如「全場主配電」或「主水塔供水」。四種「電力／供水／通風／飼料」只是**篩選類別**，不是各只能建立一個的系統實體。
3. 選母系統後按「建立下層子系統」，可分別建立「產房 A 排風扇電源」、「產房 B 排風扇電源」、「妊娠 B 第三排供水」等，各自指定棟舍／區域；**範例名稱不是預先填入你的正式豬場資料**。
4. 每個子系統可以選擇一到數個同類別上游母系統，支援同一個區域分支有多個人工確認的上游來源。關係檢查會拒絕循環連結。
5. 選擇子系統後，可用右側搜尋找到**已有**設備／管線，按「關聯」加入。設備和管線可連結多個系統；按「解除」不會刪除真實 CAD 設備。
6. **大量設備快速綁定**：在所選子系統內輸入至少 2 個字元的設備名稱、種類或棟舍關鍵字，可以先預覽搜尋結果，再按「批次關聯」一次連結最多 200 筆設備／線路；需確認對話框才會儲存，並可用原系統復原功能撤銷。
7. 下次點開時，系統樹會顯示每個子系統的直接設備數及線路數。用上方的棟舍、名稱、類別篩選，快速查看不同棟舍的系統分支。

## 關聯與現場電力／供水的差異

- `母系統 → 子系統` 表示使用者建立的**管理階層／供應邏輯**，不是系統自動確認有接線、供水或飼料輸送。
- 確切的電路還是由線路的起訖設備、開關／端子及現場核對資料判定；水路與飼料路徑保留各自原有追蹤模組。不同類別間的實際供電、供水應以設備與管線關聯表達，不能只靠系統樹。
- 子系統的 `棟舍／位置` 是**使用者輸入的文字標籤**，不會擅自新增任何物件或在 CAD 上自動拉線。
- 舊設備不會自動被歸類；需由使用者逐步建立關聯，避免按設備圖標類型猜錯供應來源。

## 資料保存及防誤刪

- 新版將 `systemNodes`（母子系統及上游 ID）與每台設備／每條管線的 `systemIds` 一起保存在原設備專案，因此舊 JSON 的 `devices`、`routes`、`photos`、`maintenance` 仍完整保留。
- 原有加密完整備份與雲端快照會包含新的架構資料；匯入舊版 V11.5 JSON，會預設為尚未建立系統架構，不會編造既有連線。
- 有子系統、設備或線路關聯的母系統不能直接刪除；應先移轉資料後才能刪除。員工唯讀模式不可新增、編輯、刪除系統或調整設備關聯。
- 本機管理者切換**不是安全身分驗證**，若要員工真正分權與跨裝置，仍需確認 Firebase 安全規則與正式網站權限。
